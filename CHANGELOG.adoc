= Changelog
:toc: left

This document details all notable changes and releases for `asciidocstring`.

== [Unreleased]

=== Added
* **Lossless Docstring Parsing and Semantic Extraction**: Upgraded `SemanticExtractorVisitor` to support composite and union types (e.g. `(int, str, optional)` -> `type_name="int | str"`, `optional=True`) across parameter sections. Added `raw_entry` tracking linking back to source AST nodes across `DocstringReturn`, `DocstringYield`, `DocstringRaise`, and `DocstringAttribute`.
* **Named Return and Yield Identification**: Extended semantic models and parsing to preserve distinct `.name` and `.type_name` on `DocstringReturn` and `DocstringYield`.
* **Lossless Griffe Bridge Identifier Preservation**: Upgraded `to_asciidoc` in `griffe_bridge.py` to preserve both element name and type annotation when converting Griffe docstring sections.
* **Sphinx reST Table Serialization**: Added `visit_table` to `ReSTSerializerVisitor` supporting compilation of AsciiDoc tables to standard Sphinx `.. list-table::` directives.
* **Ordered List Preservation**: Upgraded `ReSTSerializerVisitor` to preserve numbered and ordered list markers (`#. `) instead of serializing all items as unordered asterisks.
* **AsciiDoctrine 0.2.0a7 Compatibility Tests**: Added test suite (`test_asciidoctrine_020a7_compat.py`) validating upstream resolutions for hanging-indented list item continuation lines and backslash-escaped inline formatting delimiters.

=== Upgraded
* Bumped minimum `asciidoctrine` dependency constraint to `>=0.2.0a7` in `pyproject.toml`.

=== Fixed
* **Hanging-Indented List Item Continuations in Docstrings**: Documented and verified upstream resolution in `asciidoctrine>=0.2.0a7` for multiline list items in docstrings and Griffe docstring conversions, resolving Issue https://github.com/webmaven/asciidocstring/issues/5[#5].

== [0.1.0a7] - 2026-08-22

=== Added
* **Semantic AST Parsing & Structured Docstring Querying**: Added structured docstring semantic models (`DocstringParam`, `DocstringReturn`, `DocstringYield`, `DocstringRaise`, `DocstringReceive`, `DocstringWarn`, `DocstringAttribute`, `DocstringDeprecated`, `DocstringExample`) and `SemanticExtractorVisitor` to inspect and extract structured parameters, return types, exceptions, yield/receive types, warnings, attributes, examples, deprecations, summaries, and descriptions (Issue https://github.com/webmaven/asciidocstring/issues/3[#3]).
* **AsciiDocStringDocument Semantic Properties**: Exposed direct access properties on `AsciiDocStringDocument` (`summary`, `description`, `parameters`, `returns`, `yields`, `raises`, `receives`, `warns`, `attributes`, `deprecated`, `examples`) for effortless semantic docstring querying.
* **Griffe Ingestion Bridge**: Added `from_griffe`, `from_sections`, and `to_asciidoc` in `asciidocstring.griffe_bridge` to seamlessly bridge Griffe `DocstringSection` structures across Google, NumPy, and Sphinx conventions into `AsciiDocStringDocument` representations (Issue https://github.com/webmaven/asciidocstring/issues/4[#4]).
* **Developer Experience Enhancements**:
  ** Dual-sided parameter type parsing: supports type annotations on both Left-Hand Side terms (`` `x` (float):: ``) and Right-Hand Side descriptions (`` `x`:: (`float`) ``).
  ** Multi-syntax default value parsing: supports `Defaults to X`, `default is X`, `default=X`, `defaults: X`, etc., properly preserving floats, dotted paths, and quoted literals.
  ** Safe-mode semantic fallback: returns clean fallback values (`""`, `[]`, `None`) on malformed docstrings under `safe_mode=True`.
  ** Interactive ergonomics: added descriptive `__repr__` and `__str__` to `AsciiDocStringDocument`.
  ** Contributor onboarding: added `[project.optional-dependencies.dev]` combining test, lint, and griffe tooling.

=== Upgraded
* Bumped minimum `asciidoctrine` dependency constraint to `>=0.2.0a2` in `pyproject.toml`.

=== Metrics
* Maintained **100% total code coverage** across all library modules (646/646 statements).

== [0.1.0a4] - 2026-07-16

=== Added
* **Safe Parsing Mode**: Introduced a `safe_mode` parameter to `parse()` and `AsciiDocStringDocument`. When `safe_mode=True`, syntax errors and general parsing failures emit a non-blocking `AsciiDocStringWarning` and return a rich structured fallback AST.
* **Inline Caret Fallback**: The fallback warning AST compiles to a standard Sphinx-compatible `.. warning::` admonition block enclosing a pre-formatted `.. code-block:: asciidoc` block with a dynamically inserted caret cursor pointing to the exact column of the syntax error.
* **API Warning Class**: Exposed `AsciiDocStringWarning` at the package-level.

=== Fixed
* **TestBlock Documentation Mismatch**: Aligned attributes of the `TestBlock` class documented in `README.adoc` with the real implementation (`content`, `language`, `line_number`, `is_interactive`, `attributes`).
* **Quick Start Sample**: Corrected reference from non-existent `block.code` to `block.content` in the documentation's quick start example.

== [0.1.0a1] - 2026-07-11

=== Added
* Initial release of `asciidocstring`, a pure-Python, Pyodide-compatible AsciiDoc docstring parsing and rendering utility.
* **Docstring Preprocessor**: Strips common leading indentation using `inspect.cleandoc` and normalizes trailing lines to prevent Lark EOF errors.
* **ReST Serialization Visitor**: Recursively translates AsciiDoc docstrings into high-fidelity reStructuredText (reST) compatible with Sphinx. Supports headers, nested lists, definition lists, styled text spans, admonitions, and inline links.
* **Test Block Extractor Visitor**: Extracts executable code blocks from the docstring ASG. Supports interactive `>>>` prompts and handles both inline/positional test markers.
